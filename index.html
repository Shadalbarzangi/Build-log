2026

Billing error found in a dashboard, then closed for good

A set of customers was being charged twice, and nothing in the monthly close was shaped to catch it. I built a dashboard that put the duplicate pattern in plain view, worked the cases through to correction, and the control that followed now runs every quarter instead of depending on someone noticing.

Built with: SQL against contract and invoice data in Databricks, with the exception logic written so a reviewer sees why a line was flagged, not just that it was.

  • SQL
  • Internal control

2025–

Monthly reconciliation that flags disagreement instead of hiding it

Reconciling accounts between the ERP system and the reporting layer each month. The useful part is not the tick-off; it is that the sources are compared in a way that surfaces where they disagree, so the reported figure is something checked rather than assumed.

Built with: ERP exports and SQL queries, reconciled in Excel with the break-out kept in the same place every month so the trend is readable.

2026

Billing reminder process, rebuilt as an AI workflow

A recurring reminder run used to be worked through by hand, record by record. We rebuilt it as a prompt-driven workflow that pulls the data, applies the rules and drafts the output, so a person reviews the result instead of assembling it.

Built with: structured prompts with explicit rule sets and a fixed output format, tested against real cases until the edge cases stopped leaking through.

2026

An agent that watches for hardware coming back

Equipment sometimes returns after it has already been shipped on to a new customer, which quietly breaks what is being billed. The agent recognises the pattern, posts it into Slack on its own, and clears items once they are resolved, so nobody has to keep the list alive by hand.

Built with: a packaged Claude skill carrying its own instructions and reference logic, so the behaviour is versioned rather than remembered. Validated against a fixed set of known cases before rollout, then handed over to the rest of the team.

  • Claude agents
  • Slack
  • Anomaly detection

2026

Poisson models for football matches

A hobby that turned into a modelling exercise: estimating goal, corner and card distributions from both teams' recent form and the appointed referee's tendencies, then comparing the implied probability with the price on offer. It is a good way to learn what an edge actually has to look like before it is real.

Built with: Poisson and probability estimation, historical match and referee data, and a fixed analysis structure so every fixture is assessed the same way.

  • Poisson
  • Probability
  • Python
